# Byde — spec

A macOS menu bar app that nudges a short meditation on chosen days. Interrupts by requiring a decision, never by blocking.

## Shell
- Menu bar only (`LSUIElement`), no Dock icon. SwiftPM target `Byde`, bundle id `org.joshuakaufman.byde`.
- Menu, in order: status line · **Meditate now** submenu (3 min, 5 min, 10 min, and, when a meditation link is set, a separator and the link: favicon + label) · Settings… · About Byde · Debug submenu (Debug builds only) · Quit Byde.
- **Meditate now** starts the same full-screen flow as the nudge buttons. It works at any time, on any day, inside or outside the window. Any showing nudge panel is closed. Once the timer runs to the end the session counts as today's: status becomes done and all pending nudges are cancelled. Ending early at any point leaves today's status and schedule unchanged (a panel that was closed stays closed until the next nudge is due). The item is disabled while a session is running.
- **Status line** (no prefix; updated every second): "Meditated. [sign-off]" once a session has run to the end or the meditation link was used — the sign-off is "Great work!", "Excellent job!" or "Nicely done!", chosen by (day of year in local time) mod 3, so it is fixed all day and changes the next day; "Skipped"; "No window today" (day not enabled); "Waiting for window" (enabled day, before the window opens, nothing yet); "Window ended." (window over with no session or skip); "Nudged" (a nudge has been shown and the window is open, including after a snooze); "Waiting" (inside the window before nudge 1 appears). Done and skipped win over the time-based states.
- The website page and icon fetches (see Settings) are the only network use. No third-party dependencies.
- **Menu bar icon** ("framed pause"): drawn in code (`MenuIcon.swift`), an 18×18 pt template `NSImage` (black on transparent) so macOS tints it for light and dark menu bars; no image files. A rounded frame (x 1, y 3.5, 16×11, radius 2.5) with three dots (radius 1.3, centred at y 9, x 5.5 / 9 / 12.5). **Waiting** = frame as a 1.3 pt stroke with no fill, dots filled. **Done** = frame filled solid with the dots cut out as true transparency (even-odd fill). Done only once a session has run to the end today, from a nudge or Meditate now; every other case (before the window, during nudges, after Skip today, non-enabled days, a session ended early) shows waiting. Resets to waiting at local midnight and updates immediately on change.
- **App icon**: the done glyph (solid frame, dots cut out) in #F2EFE9 on a #2C3440 macOS rounded square, flat. Generated by `scripts/make-app-icon.swift` (colours at the top of the script) into `Assets.xcassets/AppIcon.appiconset` (16–512 pt at @1x and @2x, i.e. 16–1024 px, with Contents.json). At 32 px and below the glyph is larger and the dots slightly bigger. `build.sh` converts the PNGs to `AppIcon.icns` with `iconutil`.

## Settings (window titled "Settings", fixed 420 pt wide, height fitted to content)
A single custom pane (no tabs, no toolbar, not the default Form look). The title bar is transparent with no separator and the window background extends beneath it (`titlebarAppearsTransparent`, `titlebarSeparatorStyle = .none`, `.fullSizeContentView`, applied when the view reaches its window; the About window uses the same treatment); the "Settings" title and traffic lights stay, and extra top padding keeps the first card clear of the title bar: three rounded cards (12 pt radius, no border or shadow, no section headings) on a window background that is lighter than the cards, rows separated by hairline dividers a shade darker than the card, secondary-colour captions where useful. Light mode: window #FAFAFA, cards #F0F0F2. Dark mode: window #1C1C1E, cards #2C2C2E. Accent #3E6A8A on the day picker's selected segments and the Open at login toggle; unselected day segments show the card background with subtle dividers. System label colours elsewhere.
1. **Schedule card** — Days (M T W T F S S, joined multi-select toggle buttons, default Mon–Fri) · Window starts · Window ends (native SwiftUI `DatePicker`, hours and minutes only, `.stepperField` style with no custom styling; default 11:00 / 13:00; warns if end ≤ start). Caption under the card, built from the nudge interval constants in `Schedule.swift`: "Choose a window when you're usually free. Byde will nudge you when the window starts, again 20 minutes later if you haven't started, and once more 15 minutes before it ends."
2. **Meditation card** — the app link:
   - *Website (optional)*: placeholder "e.g. app.wakingup.com"; `https://` is added if the scheme is missing; validated on commit (Return or leaving the field) with an inline error "Enter a valid web address."; clearing the field removes the link.
   - *Label*: [16 pt favicon] label text, then a **Remove** button; max 20 characters, editable. Remove that clears URL, label and favicon (including the cached icon file).
   - Caption under the card: "Opens your meditation app instead of the built-in timer."
   - Saving a new URL fetches the page once and fills the label with `og:site_name` (skipped if it is just a hostname), else the `apple-mobile-web-app-title` / `application-name` meta tag, else the page title up to its first separator (` | `, ` – `, ` — `, ` - `, `: `), else the host. Your own label edits are never overwritten unless you change the URL.
   - Favicon: fetched once per saved URL, preferring `apple-touch-icon`, then the largest declared icon (SVG skipped), then `/favicon.ico`; cached as a 64 px PNG at `Application Support/Byde/favicon.png` and not refetched unless the URL changes (or Debug → Refetch favicon). If nothing can be fetched the SF Symbol `globe` is shown.
3. **App card** — Open at login. The system (`SMAppService.mainApp.status`) is the only source of truth; Byde stores no preference for it. The toggle is read from the status when Settings appears and each time the window becomes key, and is on only when the status is `.enabled`. Turning it on or off calls `register()` / `unregister()`, then re-reads the status and shows the real result; a failure is shown for a few seconds in the description line. If the status is `.requiresApproval` the toggle is off with "Turned off in System Settings." and an "Open Login Items" link-style button (`SMAppService.openSystemSettingsLoginItems()`); `.notRegistered` and `.notFound` show off with no extra text.

The page and icon fetches are the only network access in Byde. The app is not sandboxed (ad-hoc signed), so no network entitlement is needed.

## About window
Menu → **About Byde** opens one small fixed-size, non-resizable window (a single instance; reopening brings it to the front), centred on screen when it opens. Same style as Settings: near-white background in light mode and the same dark colours, transparent title bar with no separator, no visible title text. Centred contents, in order: the app icon (96 pt), "Byde" (28 pt semibold), "Version [CFBundleShortVersionString] ([CFBundleVersion])" in secondary colour read from the bundle (currently "Version 1.0 (1)"; `build.sh` writes both keys into Info.plist), "A gentle nudge to meditate, once a day, inside a window you choose.", and "© 2026 Joshua Kaufman" in small text, where "© 2026" is secondary and "Joshua Kaufman" is a link-style accent-coloured button that opens https://joshuakaufman.org in the default browser. Escape and Cmd-W close it.

## Nudge schedule
On enabled days, while the window is open and no session has been completed and today hasn't been skipped:
- **Nudge 1** — at window start (or 10 min after a snooze).
- **Nudge 2** — 20 min after the most recent nudge 1 if still unanswered. Same bottom-right position, soft bell, brief pulse. Skipped if it would land at or after nudge 3.
- **Nudge 3** — exactly 15 min before window end. Moves the panel to the centre, soft bell, title "Window ends at [time]." Shows only 3 min · 5 min · 10 min and Skip today (no Snooze).
- Window shorter than 20 min: nudge 1 only.
- If the Mac was asleep (or the app was closed) when nudges were due, only the most recent due nudge is shown on wake, provided the window is still open.
- Skip today or any session → no more nudges that day. After the window ends: silent until the next enabled day.

## Nudge panels
- Non-activating floating panels; never take keyboard focus; stay until answered; no close button. Nudges 1, 2 and 3 are 344 pt wide (a standard macOS notification banner; the width was not measured on this macOS version).
- Nudges 1 and 2 sit at the bottom-right of the main screen's visible frame (above the Dock), away from notifications.
- Title: nudge 1 "Ready to meditate?"; nudge 1 re-shown after a snooze "Ready now?"; nudge 2 "You've got until [window end]."; nudge 3 "Window ends at [window end]." Times use the system time format. Primary row: **3 min · 5 min · 10 min** (equal, prominent). When a meditation link is set, a full-width button above the duration row (8 pt gap between the two rows) with the same prominent blue fill, white label, height, corner radius and font as the duration buttons: the favicon on a small white rounded-square tile (18 pt, 4 pt radius, favicon inset 2 pt, so it stays visible on the blue) then the label. When a link is set the duration buttons are tonal secondary buttons instead (same size, radius, font, spacing and position): the same blue as the link button at 50% opacity (translucent) with a white label and no border. With no link the panel has only the duration row, with the duration buttons in solid blue with white text. Below that, one centred row of quiet text buttons: **Snooze · Already done · Skip today** (Snooze has the tooltip and accessibility label "Snooze for 10 minutes"; nudge 3 has no Snooze, so it shows **Already done · Skip today**).
- Snooze hides the panel and re-shows nudge 1 exactly 10 min later, which restarts the nudge 2 clock. If that would be at or after the nudge 3 time, nudge 3 fires at its normal time instead. No limit on snoozes; each is logged.
- **Already done** (source `manual`): counts as completing today's session: the panel closes, pending nudges are cancelled, status becomes done (the menu shows "Meditated." with the day's sign-off) and the menu bar icon switches to done. No timer, countdown, end screen or Focus Shortcuts. Logged as `response` (detail `already_meditated`) and `session_completed` (detail `manual`, source `manual`).
- **Meditation link** (nudge-card button, source `link`; Meditate now item, source `menu-link`): opens the URL in the default browser and counts as completing today's session: the panel closes, pending nudges are cancelled, status becomes done and the menu bar icon switches to done. No Focus Shortcuts, countdown or timer. Hidden when no link is set; with no link the cards and menu are unchanged.
- Copy is neutral and brief; no streaks, no celebration. No screen dimming.

## Meditating
- N min (from a nudge button or Meditate now): the frontmost application is recorded, then Shortcut "Byde Focus On" runs if it exists → full-screen view on the main screen showing a 10-second countdown (10, 9 … 1; not part of the duration) → the N-minute timer.
- When the timer ends: bell, then an end screen reading "[N] minutes completed." (e.g. "5 minutes completed.") and a single **Done** button (Return and Esc also trigger it). Done closes the view, runs "Byde Focus Off" if it exists, and reactivates the recorded application (if it has quit, the view just closes).
- "End early" (also Esc) works throughout: it closes the view, runs Focus Off and reactivates the recorded application. During the countdown it logs no session; after that it logs `session_ended_early`.
- Only a session whose timer runs to the end marks the day done (status and menu bar icon together), whether it started from a nudge button or Meditate now. Ending early, during the countdown or the timer, leaves the day as it was and the nudge schedule unchanged. While a session is running no nudge panels appear; one that came due is shown when the session ends early.

## Logging
- `~/Library/Application Support/Byde/log-YYYY-MM.jsonl`: append-only JSON Lines, one entry per line `{ts, event, nudge?, detail?, waited?, source?}`, one file per month (a new file starts automatically when the month changes; old files are never touched or deleted). Entries are appended without reading the file, and nothing in the app reads the log: today's state lives in memory and in the saved day state, not in the log. `ts` ISO-8601 local with offset; `waited` = seconds since the panel appeared; `source` (optional) is `nudge`, `menu`, `link`, `menu-link` or `manual` on session events.
- Events: `nudge_shown` (detail `snooze` when re-shown after a snooze), `response` (detail `snooze_10`, `skip_today`, `already_meditated`, `meditate_N`, `open_link`), `window_closed`, `session_started` (detail `N min`), `session_completed` (detail `N min`, or `link` for link sessions), `session_ended_early`, `shortcut_run`, `shortcut_missing`, `debug` (Debug builds only). (`session_started` is logged when the countdown ends.)

## Debug menu
Exists only in Debug builds (`swift build`); Release builds (`./build.sh`) have no Debug submenu and none of its code (it is wrapped in `#if DEBUG`). The `--selftest` launch flag is not part of it and ships in both.

Show today's nudge schedule (times for nudges 1–3 for the current window, plus today's state) · Icon: show waiting / Icon: show done (preview the menu bar icon without changing today's state; the next real state change overrides the preview) · Nudge 1 / 2 / 3 · Refetch favicon (fetches the icon again for the current link) · Reset today · Reveal log (opens the log folder). Panel triggers ignore the window and hold off the scheduler until answered.

## Out of scope
Analytics UI, multiple daily targets, calendar access, network.
